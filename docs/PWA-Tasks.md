# Avari.Jobs — Спецификация и план задач PWA (T1 – T7)

Данный документ консолидирует требования, архитектурные решения и спецификации задач PWA-направления, включая согласованные цели **Goal 10** и расписание пуш-уведомлений **09:00 / 18:00** в рабочие дни. (Историческая привязка: первоначальный рабочий прогон спецификаций задач T1–T7 от октября 2026 года).

---

## Архитектурный контекст и цели
Avari.Jobs — сервис учёта откликов на вакансии:
- Бэкенд: Go API, база данных SQLite (`apps/server`)
- Фронтенд: React 19, TypeScript, Vite 7 (`apps/web`)
- Общие компоненты и формы: `@avari/shared` (`packages/shared`), формы используются веб-приложением и расширением Chrome
- Интеграция PWA нацелена на автономный запуск (offline), безопасное сохранение черновиков, фоновые пуш-уведомления и удобную работу на мобильных устройствах (iOS/Android).

## T1: Устанавливаемый PWA Shell и Service Worker (Выполнено)
- **Коммиты:** `fbcac15` + `dfe25ea` (ветка `OstKost/pwa-shell`)
- **Компоненты:**
  - `apps/web/vite.config.ts` с плагином `vite-plugin-pwa` в режиме `injectManifest`
  - Кастомный Service Worker `apps/web/src/sw.ts`
  - Иконки PWA `apps/web/public/brand/icon-192.png`, `icon-192-maskable.png`, `icon-512.png`, `icon-512-maskable.png`, шорткаты `today`, `calendar`, `new`
  - Модули `apps/web/src/pwa/capabilities.ts`, `tab-coordinator.ts`, `usePwa.ts`, `components.tsx`
  - Заголовки кэширования в Go `server.go` (`sw.js` и `manifest.webmanifest` без кэша с правильными MIME)
- **Ключевые правила безопасности жизненного цикла:**
  - Обновление Service Worker активируется только по явному действию пользователя в запрашивающей вкладке
  - Перед обновлением ожидается сохранение незавершённых черновиков (`onFlushDirtyDrafts`)
  - Другие вкладки не перезагружаются принудительно; при наличии несохранённых данных обновление блокируется (fail-closed)
  - В `sw.ts` `notificationclick` не сбрасывает несохранённые формы через `WindowClient.navigate` — выполняется фокус на существующее окно либо открытие нового

## T2: Автономное чтение (Offline) и постоянство черновиков (Выполнено)
- **Коммиты:** `62678f0` + `aeadd8e` (ветка `OstKost/pwa-offline`)
- **Компоненты:**
  - Нативная реализация IndexedDB `apps/web/src/offline/db.ts` (БД `avari_offline_v1`, без внешних рантайм-зависимостей)
  - Селективное согласие (Opt-in) на офлайн-кэширование журнала (`optIn: false` по умолчанию)
  - Изоляция аккаунтов: снимки сохраняются только для пользователя с активным Opt-in
  - Модули: `broadcast.ts` (синхронизация событий между вкладками), `drafts.ts` (реестр активных черновиков), `manager.ts` (OfflineManager), `hooks.ts` (`useIsOnline`, `useOfflineSettings`, `useOfflineHydration`, `useFormDraft`), `adapters.tsx` (`OfflineApplicationForm`, `OfflineTaskForm`, `OfflineNoteForm`), `components.tsx` (`OfflineNotice`, `OfflineSettingsPanel`)
- **Правила безопасности:**
  - При выходе (Logout) или ошибках авторизации (401/403 / `avari-session-expired`) черновики и локальный кэш полностью очищаются (`handleLogout`)
  - Защита от гонок: инкремент поколения `generation` блокирует запись устаревших снимков после выхода
  - Кэшированный профиль пользователя подставляется в `/me` **только** при истинном отсутствии сети (network failure / `status: 0`), но **никогда** при 401/403 или серверных ошибках

## T3: Обработка Web Share Target (Интегрировано)
- **Цель:** Прием вакансий из внешних приложений через системное меню «Поделиться».
- **Требования:**
  - Регистрация `share_target` в манифесте: `GET /share?title=&text=&url=`
  - Валидация только безопасных HTTP(S) URL, защита от опасных схем (`javascript:`, `data:`, `file:`)
  - Сохранение полученной вакансии в `sessionStorage` с ограниченным TTL на случай, если пользователю нужно сначала войти в аккаунт
  - При отсутствии сети — открытие формы в режиме локального черновика
  - Никакого автоматического сохранения в БД без явного подтверждения пользователя
  - Показ интерфейса с инструкцией ручной вставки для неподдерживаемых браузеров

## T4: Дневные цели (Goal 10) и учет полезных действий (Бэкенд интегрирован)
- **Цель:** Мотивация регулярного поиска работы через метрику «10 действий в день».
- **Правила подсчёта очков (Goal 10):**
  - Создание вакансии: `+1` балл
  - Первый явно зафиксированный отклик / переход на этап отклика и далее: `+1` балл
  - Первое выполнение задачи или завершение интервью: `+1` балл
  - Создание вакансии сразу в статусе «отправлен отклик»: `+2` балла (создание `+1` и первый отклик `+1`)
  - Выполнение отдельных самостоятельных задач (без привязки к вакансии) также даёт `+1` балл
  - Системные действия, импорт, восстановление истории, косметические правки, заметки, создание задач и повторные отметки выполнения **никогда не дают баллов**
  - Идемпотентность и защита от дедупликации: связка `user / object / action` в неизменяемом леджере
  - Фиксация дня по локальному часовому поясу пользователя (`account timezone`) на момент совершения действия
- **API:**
  - `GET /api/v1/daily-summary` (авторизованный роут)
  - Ответ: `{ today, timezone, goal: 10, added, applied, completedTasks, completedInterviews, total, plannedTasks, plannedInterviews, completedTodayTasks, completedTodayInterviews }`

## T5: Web Push VAPID и расписание уведомлений по будням (Бэкенд интегрирован)
- **Цель:** Push-уведомления на мобильные и десктопные устройства через стандартный Web Push.
- **Требования:**
  - VAPID ключи через переменные окружения, безопасная проверка адресов push-сервисов (SSRF-защита: запрет loopback, private, link-local)
  - Подписка привязана к пользователю и конкретной сессии браузера; при выходе из аккаунта подписка аннулируется
  - Фоновый планировщик в Go: проверка раз в минуту с отменой по контексту
- **Расписание уведомлений по будням (Пн–Пт, в часовом поясе пользователя):**
  - **09:00 Утренний фокус:** план на день (запланированные задачи и собеседования раздельно) и напоминание о цели Goal 10
  - **18:00 Вечерний итог:** прогресс за день (выполненные задачи и встречи из плана + новые отклики и добавленные вакансии), общий прогресс `N/10` и слова поддержки
  - Сообщения отправляются даже при нулях; краткий русский текст без раскрытия персональных данных/имен рекрутеров
  - Очередь `outbox` с лизингом для предотвращения дубликатов при распределённых запусках

## Финальная интеграция T6 — 18 октября 2026

- Бэкенд `05288572d5ea58a92c20a4c6b343d532f3043c59` и документация `db662c7b406858d5b8154748278210650524e97e` уже объединены с сохранённой базой; цель не применялась повторно отдельно от push-бэкенда.
- Пять файлов UI из `b6aabe7ea59b3650717206ef8ed6bb57e09b2794` интегрированы: `PushSettings` в «Настройки → Общие», `DailyGoal` на главной. Успешные изменения вакансий и задач инвалидируют сводку. Разрешение уведомлений запрашивается только по клику, повторное включение блокируется до окончания запроса; компонент не регистрирует второй Service Worker.
- Выход выполняет ограниченную по времени очистку уведомлений устройства до завершения серверной сессии; истечение сессии и межвкладочный выход закрывают локальную подписку без повторного запроса авторизации. Постановка теста в очередь не считается доказательством доставки.
- `GET /share` сохраняет входящие данные до входа, очищает адрес через BrowserRouter и открывает форму только после загрузки журнала. Совпадение канонического адреса открывает существующую карточку. Ярлык `#add-vacancy` открывает пустую форму; ручная вставка доступна кнопкой «Вставить ссылку» на главной. Опасные схемы адреса не принимаются, автоматического создания записей нет.
- Верифицированная сессия активируется только после успешного живого `/me` или `/auth/login` и завершения транзакции IndexedDB, включая личный мастер установки. Кэшированные данные не активируют запись на сервер. После восстановления сети `/me` проверяется перед разрешением изменений; сообщения и баннер учитывают недоступность сервера даже при `navigator.onLine === true`.
- Снимки и черновики проверяют сохранённое поколение сессии в транзакции. Старые формы не принимают поколение повторного входа. Отказ авторизации и выход очищают данные и рассылают событие вкладкам; отключение офлайн-чтения сохраняет независимые черновики. Явное сохранение черновиков перед обновлением отклоняется при ошибке/отмене транзакции или отсутствии IndexedDB.
- В интеграции сохраняются исходные автозаполнение вакансий и импорт/экспорт журнала. Коммита поверх пользовательской базы нет: полный результат остаётся в рабочей копии; отдельный патч строится относительно сохранённых 28 файлов, а не относительно чистого HEAD.

### Границы проверки

`npm run typecheck`, 201 тест Vitest и полная сборка `npm run build` прошли. Бэкенд `go test -race ./apps/server/...` и `go vet ./apps/server/...` ранее проверены отдельным работником координатора; финальная UI-интеграция не меняла поведение Go-кода. Полный обычный браузерный прогон T6 также прошёл: `env -u AVARI_E2E_GREP AVARI_E2E=1 go test -v ./apps/server/internal/httpapi -run '^TestBrowser$' -count=1 -timeout 10m` — 30/30 тестов, 115.434 секунды для Go-пакета. Он включает личную установку/импорт, реальное расширение, исходное автозаполнение, мобильную вёрстку, офлайн-чтение списка/детали/календаря и новый приём ссылок. Тестовый вход повторяет только HTTP 429 один раз после минутного сброса лимита и требует реального ответа 200; серверный лимит не изменён. Независимая приёмка T7 ещё предстоит; её результаты сюда не включены.

Автоматические проверки не подтверждают реальную доставку через APNs/FCM/Mozilla, фоновые сроки 09:00/18:00 на физических устройствах, установку приложения ОС или матрицу Safari/Firefox. Для доставки нужны валидные VAPID-настройки, явное согласие пользователя и отдельная проверка на устройстве. VAPID по умолчанию отключён; включение требует всех трёх переменных окружения и HTTPS/localhost.

- Итог: **6/6 Chromium acceptance PASS**, 14.5 с Playwright / 15.812 с Go-пакет; готово к следующему этапу интеграции в пределах проверенной платформы.
- Проверена собственная production-сборка `npm run build` через Go HTTP-сервер, не Vite dev: `env -u AVARI_E2E_GREP -u AVARI_PWA_E2E_GREP AVARI_PWA_ARTIFACT_DIR=/tmp/avari-pwa-run/T7/screenshots AVARI_PWA_E2E=1 go test -v ./apps/server/internal/httpapi -run '^TestPWAAcceptance$' -count=1 -timeout 10m`.
- Подтверждены единственная ссылка manifest, корректные MIME/no-cache для manifest и SW, отсутствие API/файлов в CacheStorage; первая установка не перезагружает документ.
- Реальная смена SW A→B требует обычного клика «Обновить» внутри открытого native dialog; последний ввод перед кликом сохраняется и восстанавливается. Другой документ и введённая задача другой вкладки сохраняются без перезагрузки. Найденная блокировка баннера модальным top layer и дублирование manifest исправлены владельцем UI и перепроверены.
- Полностью закрыт Chromium, затем новый процесс с тем же временным профилем запущен офлайн: не-корневой маршрут восстанавливает настоящую карточку, заметку и календарную задачу. Офлайн-форма оставляет только локальный черновик, API-мутаций нет; серверные записи после восстановления сети не изменены.
- Opt-out и очистка кэша сохраняют черновики; logout очищает кэш/черновики обеих вкладок, задержанный autosave не восстанавливает данные; второй аккаунт не получает данные первого. Настоящее истечение изолированной SQLite-сессии даёт наблюдаемый `/me` 401 и запрещает офлайн-fallback; повторный вход снова сохраняет черновики.
- Share до входа сохраняется для подтверждения без автосоздания, канонический дубль открывает существующую карточку, опасная схема отклоняется, ярлык открывает пустую форму. Push проверен моками: без запроса разрешения при mount, только по жесту, тест ставится в очередь, отключается текущий endpoint.
- Платформа: macOS arm64, настоящий Chromium 156.0.8078.4. Safari/Firefox, физические iOS/Android, установка ОС и реальная доставка APNs/FCM/Mozilla не проверялись; постановка в очередь не доказывает доставку. A/B fixture изменяет HTML и согласованную precache revision одной production-сборки; обновление JS-схемы отдельным релизом не моделируется.

T6); после неё независимо повторены production build и все шесть acceptance-кейсов. Полные ранее успешные наборы повторно не запускались. После шести успешных кейсов синхронизирована финальная текстовая правка iOS-инструкции; по решению координатора для неё повторены только typecheck и полная сборка, а шесть поведенческих кейсов не повторялись.
