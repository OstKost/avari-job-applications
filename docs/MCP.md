# MCP / Codex

MCP позволяет добавлять, находить и редактировать вакансии в журнале Avari.Jobs из диалога с агентом. Работает с онлайн-, локальным и собственным экземпляром приложения. Локальный сервер должен быть запущен и доступен компьютеру с Codex.

## Подключение

1. Войдите на сайт и откройте **Настройки → MCP / Codex**.
2. Укажите название подключения и создайте токен. Он действует 90 дней; полный секрет показывается только один раз. В базе хранится его хеш. Можно создать до 20 токенов.
3. Задайте `AVARI_JOBS_MCP_TOKEN` в окружении процесса Codex. Для разового запуска в bash/zsh можно ввести секрет без отображения на экране и без записи в историю команд:

   ```sh
   read -rs AVARI_JOBS_MCP_TOKEN
   export AVARI_JOBS_MCP_TOKEN
   codex
   ```

4. Добавьте в `~/.codex/config.toml`:

   ```toml
   [mcp_servers.avari_jobs]
   url = "https://jobs.avari.dev/mcp"
   bearer_token_env_var = "AVARI_JOBS_MCP_TOKEN"
   ```

   Для локальной или собственной установки замените URL адресом этого экземпляра с путём `/mcp`. Настройки приложения показывают готовую конфигурацию с текущим адресом. Для сервера в интернете используйте HTTPS.
5. Перезапустите Codex из окружения с переменной и проверьте `codex mcp list`. OAuth-вход через `codex mcp login` для этой интеграции не используется.

## Использование

- «Разбери вакансию: https://…» — агент подготовит карточку и предложит сохранить.
- «Поменяй зарплату на 250–300 тысяч рублей до вычета налогов и сохрани» — применит правки и добавит карточку.
- «Сохрани эту вакансию сразу: https://…» — сохранит без дополнительного вопроса в диалоге, если известны компания и позиция. Настройки подтверждений самого Codex могут потребовать отдельное разрешение инструмента.

Подготовка не создаёт серверного черновика. Для записи обязательны компания и позиция. Неизвестные необязательные поля остаются пустыми. MCP сохраняет текущие поля карточки, включая зарплату, локацию, формат работы и контакт рекрутера; группа и теги добавляются по просьбе. Этап новой записи — «Сохранено», состояние — активное. Отклики работодателям не отправляются.

Семь поддерживаемых площадок разбирает существующий серверный парсер. Для других адресов или недоступных страниц агент использует свои инструменты чтения. Их наличие зависит от среды Codex; если прочитать страницу нельзя, вставьте текст вакансии в диалог. Сервер не загружает произвольные сайты и не использует дополнительный LLM API.

Дубли определяются в пределах аккаунта: по канонической ссылке известных площадок, для остальных сайтов — по URL без fragment и известных tracking-параметров. Значимые параметры, например идентификатор вакансии, сохраняются. Разные адреса одной вакансии на произвольном сайте могут потребовать ручной проверки. Найденный дубль возвращается ссылкой и не изменяется.

## Поиск и редактирование

- «Найди активные вакансии Go в Москве» — поиск в сохранённом журнале.
- «Покажи избранные вакансии с тегом Backend и открытыми задачами» — сочетание фильтров.
- «Найди вакансии, где упоминается распределённая система» — поиск по текстовым полям карточки.
- «Измени зарплату в этой карточке на 250–300 тысяч рублей до вычета налогов» — редактирование по явной команде без дополнительного подтверждения.

Если подходят несколько карточек, агент уточняет выбор. Перед изменением он читает актуальную карточку. При конфликте версии сервер возвращает текущие данные; агент сравнивает их и согласует конфликтующие правки, не перезаписывая запись автоматически. Можно менять поля карточки, этап, состояние, результат закрытия, даты, избранное, группу, теги и значения пользовательских полей. Заметки, задачи и системные поля не редактируются.

## Доступ и отзыв

Токен разрешает подготовку, добавление, поиск, чтение и редактирование вакансий только в аккаунте владельца. Эти возможности доступны также ранее созданным MCP-токенам. Токен не открывает обычный API. Токены веб-сессий и расширения не работают на MCP.

Раздел настроек показывает сроки и последнее использование. Кнопка **«Отозвать»** немедленно отключает токен для последующих запросов. Смена/сброс пароля и блокировка аккаунта также отзывают MCP-токены. Не отправляйте токен агенту в сообщении и не добавляйте его в Git.

## Контракт и проверка

Streamable HTTP: `/mcp`, авторизация `Authorization: Bearer <MCP-токен>`. Управление токенами через веб-сессию с CSRF: `GET/POST /api/v1/mcp/tokens`, `DELETE /api/v1/mcp/tokens/{id}`. Секрет возвращается только при создании; данные токенов исключены из экспорта журнала.

Инструменты:

- `prepare_vacancy({url, fields?})` возвращает `url`, `fields`, `missingRequired`, `warnings`, `needsAgentExtraction`, `existing?`, `idempotencyKey`. Переданные поля заменяют распознанные; объект зарплаты заменяется целиком.
- `save_vacancy({url, fields, idempotencyKey})` возвращает `status: created | already_exists` и `application: {id, company, position, link}`. При повторе используйте тот же ключ. Ключи ограничены аккаунтом. Существующие карточки не обновляются.
- `search_vacancies({query?, filters?, limit?, offset?})` возвращает `applications` (карточки с `id`, `version` и `link`), `total`, `hasMore`.
- `get_vacancy({id})` возвращает полную карточку с текущей версией и ссылкой, без заметок и задач.
- `get_vacancy_metadata({})` возвращает `stages`, `states`, `outcomes`, используемые `groups`, `tags` и определения пользовательских `fields`. Поле с `role: "priority"` определяет фильтр приоритета.
- `update_vacancy({id, version, fields})` применяет частичные изменения и возвращает обновлённую карточку.

Фильтры поиска: `stage`, `state`, `favorite`, `group`, `ungrouped`, `tag`, `priority`, `hasTask`, `company`, `position`, `location`, `workFormat`. Разные фильтры соединяются через AND. Компания, должность, локация и формат сравниваются по подстроке без учёта регистра; остальные значения — точно. `favorite` и `hasTask` принимают также `false`; `hasTask` учитывает только открытые задачи. `group` и `ungrouped: true` несовместимы.

`query` ищет подстроку без учёта регистра отдельно в компании, должности, URL, локации, формате, контакте рекрутера, группах, тегах и пользовательских полях типов `text` и `select`. Заметки не участвуют. Без фильтров поиск включает закрытые карточки. Порядок: дата сохранения по убыванию, время создания по убыванию, ID по возрастанию. Размер страницы по умолчанию — 20, допустимый `limit` — 1–100, `offset` — целое от 0. Список при изменениях журнала между запросами может сдвигаться.

В `fields` инструмента редактирования доступны `company`, `position`, `url`, `salary`, `location`, `workFormat`, `recruiter`, `companyLogo`, `groups`, `tags`, `favorite`, `stage`, `state`, `outcome`, `savedDate`, `appliedDate`, `custom`. Пропущенные поля сохраняются; пустая строка очищает необязательное строковое поле, `[]` очищает группу или теги. `salary` заменяется целиком, включая валюту, период и налоги. `custom` изменяет только переданные ключи; значение `null` удаляет соответствующее пользовательское значение. При закрытии карточки требуется допустимый `outcome`. Источник изменений в истории — MCP.

Конфликт возвращается с `isError: true`; текст ошибки содержит JSON с `status: 409`, `message` и актуальной карточкой `current`. При смене URL на ссылку уже существующей вакансии возвращается конфликт с найденной карточкой.

Ограничения на токен: 30 подготовок и 10 сохранений в минуту; инструменты чтения журнала делят квоту 60 запросов в минуту, редактирование — 10 запросов в минуту. Ошибки инструмента возвращаются с `isError`; отсутствие/истечение/отзыв токена — HTTP 401. Токен проверяется при каждом запросе. Инструкции по согласию пользователя исполняет агент; сервер не может проверить содержание диалога, поэтому write-инструмент обозначен как изменяющий данные.

Для ручной проверки запустите `npx @modelcontextprotocol/inspector`, выберите Streamable HTTP, адрес `/mcp` и Bearer-токен тестового аккаунта. Проверьте список шести инструментов, подготовку без записи, сохранение, повтор запроса, дубль, поиск, метаданные, чтение карточки, частичное изменение, конфликт версии и отказ после отзыва. Затем проверьте оба сценария диалога в Codex: предложение сохранения и прямую команду сохранить.

На production `/mcp` использует существующий HTTPS reverse proxy. Режим trusted proxy совместим с проверкой Host по настроенному публичному Origin; для локального сервера сохранена защита от DNS rebinding. В dev-режиме Vite проксирует `/mcp` на API вместе с `/api`.
