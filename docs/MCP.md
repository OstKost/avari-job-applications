# MCP / Codex

MCP позволяет добавлять вакансии в Avari.Jobs из диалога с Codex. Работает с онлайн-, локальным и собственным экземпляром приложения. Локальный сервер должен быть запущен и доступен компьютеру с Codex.

## Подключение

1. Войдите на сайт и откройте **Настройки → MCP / Codex**.
2. Укажите название подключения и создайте токен. Он действует 90 дней; полный секрет показывается только один раз. В базе хранится его хеш. Можно создать до 20 токенов.
3. Задайте `AVARI_JOBS_MCP_TOKEN` в окружении процесса Codex. Для разового запуска в bash/zsh можно ввести секрет без отображения на экране и без записи в историю команд:

   ```sh
   read -rs AVARI_JOBS_MCP_TOKEN
   export AVARI_JOBS_MCP_TOKEN
   codex
   ```

4. Добавьте в `~/.codex/config.toml`:

   ```toml
   [mcp_servers.avari_jobs]
   url = "https://jobs.avari.dev/mcp"
   bearer_token_env_var = "AVARI_JOBS_MCP_TOKEN"
   ```

   Для локальной или собственной установки замените URL адресом этого экземпляра с путём `/mcp`. Настройки приложения показывают готовую конфигурацию с текущим адресом. Для сервера в интернете используйте HTTPS.
5. Перезапустите Codex из окружения с переменной и проверьте `codex mcp list`. OAuth-вход через `codex mcp login` для этой интеграции не используется.

## Использование

- «Разбери вакансию: https://…» — агент подготовит карточку и предложит сохранить.
- «Поменяй зарплату на 250–300 тысяч рублей до вычета налогов и сохрани» — применит правки и добавит карточку.
- «Сохрани эту вакансию сразу: https://…» — сохранит без дополнительного вопроса в диалоге, если известны компания и позиция. Настройки подтверждений самого Codex могут потребовать отдельное разрешение инструмента.

Подготовка не создаёт серверного черновика. Для записи обязательны компания и позиция. Неизвестные необязательные поля остаются пустыми. MCP сохраняет текущие поля карточки, включая зарплату, локацию, формат работы и контакт рекрутера; группа и теги добавляются по просьбе. Этап новой записи — «Сохранено», состояние — активное. Отклики работодателям не отправляются.

Семь поддерживаемых площадок разбирает существующий серверный парсер. Для других адресов или недоступных страниц агент использует свои инструменты чтения. Их наличие зависит от среды Codex; если прочитать страницу нельзя, вставьте текст вакансии в диалог. Сервер не загружает произвольные сайты и не использует дополнительный LLM API.

Дубли определяются в пределах аккаунта: по канонической ссылке известных площадок, для остальных сайтов — по URL без fragment и известных tracking-параметров. Значимые параметры, например идентификатор вакансии, сохраняются. Разные адреса одной вакансии на произвольном сайте могут потребовать ручной проверки. Найденный дубль возвращается ссылкой и не изменяется.

## Доступ и отзыв

Токен разрешает только подготовку карточек, проверку совпадения ссылки и добавление вакансий в аккаунт владельца. Он не открывает обычный API, поиск по журналу или редактирование записей. Токены веб-сессий и расширения не работают на MCP.

Раздел настроек показывает сроки и последнее использование. Кнопка **«Отозвать»** немедленно отключает токен для последующих запросов. Смена/сброс пароля и блокировка аккаунта также отзывают MCP-токены. Не отправляйте токен агенту в сообщении и не добавляйте его в Git.

## Контракт и проверка

Streamable HTTP: `/mcp`, авторизация `Authorization: Bearer <MCP-токен>`. Управление токенами через веб-сессию с CSRF: `GET/POST /api/v1/mcp/tokens`, `DELETE /api/v1/mcp/tokens/{id}`. Секрет возвращается только при создании; данные токенов исключены из экспорта журнала.

Инструменты:

- `prepare_vacancy({url, fields?})` возвращает `url`, `fields`, `missingRequired`, `warnings`, `needsAgentExtraction`, `existing?`, `idempotencyKey`. Переданные поля заменяют распознанные; объект зарплаты заменяется целиком.
- `save_vacancy({url, fields, idempotencyKey})` возвращает `status: created | already_exists` и `application: {id, company, position, link}`. При повторе используйте тот же ключ. Ключи ограничены аккаунтом. Существующие карточки не обновляются.

Ограничения на токен: 30 подготовок и 10 сохранений в минуту. Ошибки инструмента возвращаются с `isError`; отсутствие/истечение/отзыв токена — HTTP 401. Токен проверяется при каждом запросе. Инструкции по согласию пользователя исполняет агент; сервер не может проверить содержание диалога, поэтому write-инструмент обозначен как изменяющий данные.

Для ручной проверки запустите `npx @modelcontextprotocol/inspector`, выберите Streamable HTTP, адрес `/mcp` и Bearer-токен тестового аккаунта. Проверьте список двух инструментов, подготовку без записи, сохранение, повтор запроса, дубль и отказ после отзыва. Затем проверьте оба сценария диалога в Codex: предложение сохранения и прямую команду сохранить.

На production `/mcp` использует существующий HTTPS reverse proxy. Режим trusted proxy совместим с проверкой Host по настроенному публичному Origin; для локального сервера сохранена защита от DNS rebinding. В dev-режиме Vite проксирует `/mcp` на API вместе с `/api`.
