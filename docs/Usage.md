# Avari.Jobs — журнал откликов

Монорепозиторий Avari.Jobs: Go + SQLite, React-сайт, Chromium MV3-расширение и консольное администрирование. Интерфейс на русском, мобильная и desktop-компоновка. Тёмная тема по умолчанию, светлая переключается и сохраняется.

## Части проекта

- `apps/server` — HTTP-сервис, общая бизнес-логика, миграции и отдельный TUI (`cmd/admin`).
- `apps/web` — React + TypeScript + Vite.
- `apps/extension` — popup, service worker и DOM-парсеры открытых страниц hh.ru, LinkedIn, Getmatch, Hirify, Geekjob, Хабр Карьеры и Huntflow.
- `packages/shared` — UI-компоненты, темы, клиент API и типы, сгенерированные из OpenAPI.
- `deploy` — systemd, Caddy и примеры конфигурации. Корневой `compose.yaml` — Docker.

Требования: Go 1.27.1+, Node.js 22.12+ (проверено на Node 26), npm, `make`, `zip`. Docker нужен только для контейнерного запуска. SQLite встроена; отдельный сервер базы и CGO не нужны.

## Быстрый запуск

```sh
npm ci
make build
./bin/avari
```

Открыть http://localhost:47831, зарегистрироваться, затем в другом терминале:

```sh
./bin/avari-admin
```

В TUI выбрать заявку, нажать `a`, подтвердить Enter. Экран ожидания на сайте обновляется автоматически. Создавать администратору отдельный веб-аккаунт не нужно: TUI доступен через локальные права ОС. В обычном серверном режиме регистрации требуют одобрения. В личной локальной версии аккаунт создаётся мастером установки без TUI.

Для разработки после первой сборки:

```sh
AVARI_ORIGIN=http://localhost:5173 make api
# В другом терминале:
make dev
```

Vite доступен на http://localhost:5173. Для авторизации с dev-сайта сервер нужно запускать с `AVARI_ORIGIN=http://localhost:5173 make api`. Vite проксирует `/api` на Go-сервис. На production origin должен точно соответствовать внешнему HTTPS-адресу.

## Веб-интерфейс

На телефоне основные разделы доступны в нижней навигации; дополнительные разделы, переключатель темы и выход — через кнопку «Открыть меню» в заголовке. На большом экране используется боковая панель. Дневная цель и прогресс открываются пунктом «Цели»; окно закрывается кнопкой, нажатием вне него или Escape.

При переключении между входом, регистрацией и восстановлением сохраняются email и адрес назначения, а пароль очищается. Если аккаунт уже создан, но автоматический вход не удался, войдите повторно. На экране подтверждения аккаунта временная ошибка проверки статуса не закрывает экран: используйте «Повторить». Подключение Telegram отдельно показывает загрузку и ошибку доступности; истёкший или отменённый запрос можно начать заново.

Главная страница показывает обзор дня: текущие задачи, последние вакансии, активные отклики, интервью и офферы. Календарь доступен в отдельном разделе: выберите месяц и день, чтобы увидеть задачи и встречи в повестке.

В «Откликах» можно группировать записи по этапу, состоянию, группе или приоритету, сворачивать группы, сортировать список, переключать таблицу, карточки и статистику. Группы показывают записи текущей страницы (по 20), статистика учитывает всю выборку после фильтров. Настройки вида, фильтры, поиск, сортировка и пагинация сохраняются в браузере отдельно для каждого аккаунта и восстанавливаются при возврате со страницы карточки отклика. Светлая и тёмная темы доступны на всех страницах.

Бейджи этапа и состояния вакансий в таблице, карточках и деталях отклика работают как компактные выпадающие переключатели без изменения resting-дизайна. Выбор закрытого состояния («Закрыт») требует обязательного указания результата (outcome) в модальном окне.

Раздел «Избранные вакансии» (`/favorites`) и пункт в боковом меню позволяют работать со списком избранных вакансий с сохранением всех возможностей поиска, фильтрации и группировки. Переключение отметки «В избранном» доступно прямо из строки таблицы, карточки и детальной страницы.

Раздел «Резюме» (`/resumes`) в боковом меню позволяет управлять именованными логическими резюме и их версиями (поддерживаются форматы PDF, MD, TXT, DOCX, DOC, ODT, RTF до 20 МБ на файл). При экспорте журнала в формате JSON файлы резюме исключаются (сохраняются только в полной резервной копии SQLite).

Для активных вакансий без значимой активности более 240 часов (10 дней) отображается кнопка предупреждения о неактивности, открывающая действия: планирование задачи «Связаться по вакансии» на следующий рабочий день, приостановка или закрытие с указанием результата.

### Автозаполнение по ссылке на вакансию
При добавлении новой вакансии вручную или через форму вставки ссылки («Вставить ссылку» на главной странице) доступно автозаполнение данных:
- Поддерживаются ссылки на вакансии hh.ru, LinkedIn, Getmatch, Hirify, Geekjob, Хабр Карьеру и Huntflow.
- При вставке валидного URL в поле формы или использовании буфера обмена веб-клиент обращается к эндпоинту `POST /api/v1/vacancies/preview`.
- Сервер извлекает доступные метаданные (название должности, компанию, зарплатную вилку и валюту, локацию, формат работы и логотип) на основе OpenGraph, JobPosting JSON-LD и DOM-разметки открытой страницы.
- При вставке URL найденные поля подставляются автоматически и могут заменить заполненные значения; правки во время ожидания ответа сохраняются. Предложение из буфера обмена применяется кнопкой «Заполнить». Проверьте поля и сохраните карточку отдельно. Если загрузка недоступна, продолжите вручную.

### Telegram-бот

В онлайн-версии [@AvariJobsBot](https://t.me/AvariJobsBot) помогает подтвердить регистрацию, войти без пароля и вести журнал. Для существующего аккаунта откройте настройки сайта, нажмите «Подключить Telegram», сверьте данные в боте и подтвердите привязку на сайте. После привязки можно входить через Telegram на сайте и в расширении; каждый вход требует отдельного подтверждения с совпадающим кодом.

Команды: `/add` — вакансия из ссылки или текста с проверкой перед сохранением; `/search` — поиск и карточки журнала; `/today` — задачи на сегодня и просроченные; `/week` — ближайшие семь дней; `/settings` — подключение и сводки; `/cancel` — отмена диалога. Из карточки доступны этапы, состояния, заметки и задачи. Сообщение или ссылка сами по себе не сохраняют вакансию: подтвердите карточку.

Утренние и вечерние сводки независимы от Web Push и изначально выключены. Их можно включить отдельно: по будням в 09:00 и 18:00 в часовом поясе аккаунта. Telegram доступен только на сервере с настроенной интеграцией и отключён в персональном локальном режиме. Отключение привязки отменяет незавершённые Telegram-входы; существующие сессии сайта сохраняются.



### Статистика

Страница «Статистика» в меню рабочего пространства показывает:

- **Активность за последние 90 дней:** одно создание или содержательное изменение вакансии, заметки либо связанной задачи считается одним действием. Учитываются сайт и расширение; автоматические напоминания и сохранения без изменений исключаются. День определяется часовым поясом аккаунта, импортированная история сохраняет исходные даты.
- **Отклики по дням:** столбцы за последние 7, 30, 90 дней либо свой диапазон. Дата берётся из поля «Дата отклика», цвет — из текущего этапа. После продвижения вакансии цвет её сегмента в прошлом дне меняется. Вакансии без даты отклика не учитываются.
- **Распределение по состояниям и этапам:** две круговые диаграммы по всему журналу, включая сохранённые вакансии и закрытые процессы. Периоды остальных графиков на них не влияют.

Количество и доли доступны в легендах и подсказках при наведении, фокусе с клавиатуры или касании. Плитки отражают только действия, присутствующие в сохранённой истории.

## Расширение

После `make build` готова папка `apps/extension/dist` и архив `dist/avari-extension.zip`. На рабочем сайте архив доступен на странице `/extension`.

1. Открыть `chrome://extensions`, включить режим разработчика.
2. Нажать «Загрузить распакованное расширение», выбрать `apps/extension/dist`.
3. В расширении выберите «Онлайн сохранение» или «Локальное сохранение» и войдите в аккаунт. Адреса уже заполнены; изменить их можно в «Настройках адресов». Для каждого режима адрес сохраняется отдельно. Авторизация расширения отдельная от сайта.
4. Открыть карточку вакансии на hh.ru, linkedin.com, getmatch.ru, hirify.me, geekjob.ru career.habr.com или huntflow.io либо раздел откликов hh.ru, Getmatch или Hirify. Нажать значок расширения, чтобы открыть мини-окно на странице. Мини-окно предназначено для быстрого сохранения вакансии или отклика, выбора группы и смены этапа сохранённой вакансии. Его можно передвигать за верхнюю полосу и полностью закрывать крестиком. Повторное открытие — из плагина. При обнаружении вакансии расширение автоматически показывает свёрнутую панель, в том числе после перезагрузки страницы; сохранение требует подтверждения.

#### Вход через Telegram в расширении

Начиная с версии 1.10.0 можно выбрать «Войти через Telegram», если выбранный сервер поддерживает этот способ входа. Нужен активный аккаунт с Telegram, уже подключённым в настройках сайта. Кнопка открывает отдельную вкладку расширения: перейдите в бота, сверьте код и подтвердите вход. После сообщения «Вы вошли» вернитесь к вакансии.

Запрос действует пять минут. Закрытие popup не прерывает вход: вкладку входа можно открыть повторно. При истечении срока или отказе в боте начните заново. Смена сервера прекращает текущий вход. На персональном локальном сервере Telegram отключён; вход по email и паролю сохраняется во всех режимах.

Группа вакансии задаётся пользователем в форме добавления или редактирования: можно выбрать существующее название или добавить новое. У вакансии одна группа и до 30 тегов. При обновлении старого журнала первая группа сохраняется, остальные группы переносятся в теги. В журнале есть фильтр по группе и вариант «Без группы». Снятие выбора в форме убирает вакансию из группы; пустые группы исчезают из списка. Группы хранятся на сервере вместе с вакансией.

Поддерживаются HTTPS-страницы следующих сайтов и их поддоменов:

- hh.ru: карточки `/vacancy/<id>` и список откликов `/applicant/negotiations`.
- LinkedIn: карточки `/jobs/view/<id>` и `/jobs/view/<название>-<id>`. На `/jobs/search`, `/jobs/search-results` и `/jobs/collections` карточка читается при наличии `currentJobId` и совпадении ID с загруженной карточкой.
- Getmatch: карточки `/vacancies/<id>` и `/vacancies/<id>-<название>`, список откликов `/applications`.
- Hirify: карточки `/jobs/<id>` и `/jobs/<id>-<название>`, таблица откликов `/applications`. Строки, ведущие на другие площадки, не сопоставляются с вакансиями Hirify.
- Geekjob: карточки `/vacancy/<id>`.
- Хабр Карьера: карточки `/vacancies/<id>`.
- Huntflow: карточки `https://<компания>.huntflow.io/vacancy/<id>`.

Парсер читает текущую DOM-разметку и её изменения; не открывает следующие страницы, не использует API площадок и не отправляет cookies, пароль или переписку. Зарплата и основные поля извлекаются из DOM, с резервным чтением публичного JobPosting JSON-LD. Не найденное поле остаётся пустым и уточняется вручную.

На странице откликов hh.ru расширение также предлагает добавить отсутствующие в журнале вакансии с датой отклика за последний календарный месяц (от соответствующего числа предыдущего месяца до сегодня включительно). Компания, позиция и дата берутся из строки отклика; строки с неизвестной датой пропускаются. Предложения появляются в приложении и расширении, запись создаётся только по кнопке «Добавить в журнал». Повторное чтение и отклонение не создают новых предложений о той же вакансии. Для проверки следующих страниц списка откройте их на hh.ru.

Для новых сайтов вакансии сопоставляются по площадке и ID в нормализованной ссылке: поддомены, суффиксы названий и параметры перехода не создают дублей. Ранее сохранённые вручную ссылки также сопоставляются. Поле `hhId` сохраняет прежнее значение только для hh.ru. Расширение читает явно показанные состояния в карточках, включая архив Getmatch и статус отклика LinkedIn. В Getmatch читается отдельная отметка состояния отклика, без смешивания с отметкой снятой вакансии. В Hirify читается выбранный этап строки; HR-интервью, финальное интервью и оффер могут предложить продвижение этапа, а отсутствие ответа не означает отказ. Если площадка не показывает состояние в поддерживаемом элементе карточки или списка, этап обновляется вручную. Трекер LinkedIn `/jobs-tracker` пока не разбирается.

Черновики вакансий, задач и заметок сохраняются сразу при вводе в локальном хранилище расширения и восстанавливаются после закрытия popup или перезагрузки страницы. Они разделены по серверу, пользователю и вакансии; для ручного добавления используется отдельный черновик. Успешное сохранение или «Отмена» очищают текущий черновик.

Системные уведомления включаются отдельно и не раскрывают компанию или результат. Badge показывает ожидающие предложения. Токен хранится в `chrome.storage.local` с доступом только из доверенных контекстов расширения. Content script не получает токен.

Повторное открытие и парсинг не создают дублей. Наличие вакансии не означает отправленный отклик, отсутствие строки не означает отказ. Неизвестные статусы сохраняются как внешнее наблюдение без автоматического изменения этапа. Изменившуюся разметку площадок нужно проверять на живой странице: тестовые DOM-примеры не заменяют такую проверку.

11 октября 2026 года основные поля проверены на публичной карточке hh.ru: название, компания, зарплата, адрес и формат работы. В разделе откликов после входа проверены текущая структура строк и статусы «Не просмотрен», «Просмотрен», «Собеседование», «Отказ». Регрессионные примеры списка обезличены; личные вакансии и переписка в репозиторий не сохраняются.

11 октября 2026 года также проверены публичные DOM-карточки [Getmatch](https://getmatch.ru/vacancies/19879-golang-razrabotchik) (заголовок, компания, зарплата, локация, формат работы, архив) и [Hirify](https://hirify.me/jobs/1090398-sistemnyi-analitik-rest-postgresql-kafka) (основные поля и JobPosting JSON-LD). После входа также проверены современная SDUI-разметка карточки LinkedIn и `/jobs/search-results`, список откликов Getmatch и таблица этапов Hirify. Настоящий парсер проверен на сохранённых браузером страницах: название, компания, локация и формат работы LinkedIn; явный отказ Getmatch; этап отклика Hirify. В проверенном аккаунте LinkedIn не было отправленных заявок, поэтому реальное состояние отправленного отклика там не подтверждено. Сохранение вакансии и начатая заявка не считаются отправленным откликом. Для регрессий используются обезличенные минимальные DOM-примеры; временные копии авторизованных страниц удаляются после проверки.

## Возможности

Регистрация с одобрением, блокировка и отзыв сессий; ручное добавление и редактирование вакансий; шесть этапов; активный/приостановленный/закрытый процесс; результаты закрытия; зарплата, контакты, заметки и история; задачи и интервью; календарь сегодня + шесть дней и просроченные задачи; поиск и фильтры; до пяти custom-полей и 1000 вакансий на пользователя; предложения с редактированием, подтверждением и обработкой конфликтов.

В календаре используется часовой пояс аккаунта. Даты без времени не конвертируются через UTC; история хранит UTC-моменты. Блокировка и сброс пароля отзывают все сессии. Пароли не восстанавливаются письмом — администратор задаёт новый через TUI.

## Подписной календарь

В календаре нажмите «Подписаться» → «Создать ссылку подписки». Та же настройка доступна в разделе «Настройки». У каждого пользователя своя секретная ссылка `.ics`, доступная календарным сервисам без входа в Avari.Jobs. Она даёт только чтение событий этого пользователя, без доступа к остальному API.

- **Apple:** нажмите «Apple Календарь» или добавьте ссылку через «Добавить подписной календарь». [Инструкция Apple](https://support.apple.com/ru-ru/102301).
- **Google:** в браузере на компьютере выберите «Другие календари» → «Добавить по URL» и вставьте ссылку. [Инструкция Google](https://support.google.com/calendar/answer/37100?hl=ru).
- **Яндекс:** в разделе «Подписки» нажмите «Добавить» и вставьте ссылку в «Адрес календаря». [Инструкция Яндекса](https://yandex.ru/support/yandex-360/customers/calendar/web/ru/data-exchange/subscribe-other-calendar).

Лента включает все открытые задачи и интервью, включая даты за пределами текущей недели. Задачи без времени отображаются на весь день; время встреч переводится в UTC из часового пояса аккаунта с учётом сезонного времени. Длительность не задаётся, поскольку в Avari.Jobs хранится только время начала. Название события содержит задачу и компанию; описание — тип события и позицию, ссылка ведёт в Avari.Jobs. Контакты, заметки и зарплата в ленту не включаются.

После редактирования лента сразу возвращает актуальные данные. Идентификатор события остаётся прежним при переносе; выполненные задачи исчезают. Внешний календарь сам выбирает период проверки, поэтому обновление может появиться через несколько часов. Яндекс указывает интервал от нескольких часов до двух дней. Это подписка для просмотра: редактируйте события в Avari.Jobs. Разовый импорт скачанного файла не получает обновления.

«Сменить ссылку» отзывает прежнюю ссылку и требует повторного подключения сервисов; «Отключить подписку» прекращает доступ. Блокировка, сброс пароля и восстановление базы также отзывают ссылки. Выход из Avari.Jobs и отзыв обычных сессий не отключают подписку. Уже загруженные события могут оставаться во внешнем календаре до удаления подписки там.

Для Apple, Google и Яндекса Avari.Jobs должен быть доступен по внешнему HTTPS-адресу, указанному в `AVARI_ORIGIN`; localhost эти сервисы прочитать не смогут. Секретные URL не следует публиковать или сохранять в журналы доступа прокси.

API: `GET /api/v1/calendar/subscription` возвращает текущую ссылку (пустую при отключении); `POST` включает подписку с сохранением существующего адреса; `PUT` меняет адрес; `DELETE` отключает её. Управление требует активной сессии и CSRF для веб-сессий. `GET`/`HEAD /api/v1/calendar/feed/<token>.ics` читают живую ленту; `ETag` и `If-None-Match` позволяют получить `304`, если содержимое не изменилось. Миграция схемы 3 добавляет таблицу подписок автоматически, старые задачи совместимы.

## Проверки

```sh
make build test
npx playwright install chromium
make e2e
npm audit
```

E2E поднимает настоящий Go-сервис на случайном локальном порту с временной SQLite. Тестовые аккаунты и одобрение существуют только внутри Go test-бинарника; production не содержит обхода авторизации. Браузерные тесты используют disposable Chromium-профиль, включая настоящее MV3-расширение. Страницы площадок в автоматических тестах — синтетические DOM-fixtures, без внешних откликов и изменений на площадках.

`make release` создаёт Linux-бинарники amd64/arm64 и архив расширения. API-контракт: `docs/openapi.json`; после его изменения выполнить `npm run generate:api`. Go-тесты проверяют изоляцию, сессии, конкуренцию, лимиты, подтверждения, историю и восстановление базы.

## Docker

```sh
make build
docker compose up --build -d app
# Одобрение пользователей:
docker compose run --rm admin
```

Сайт доступен только на локальном http://localhost:47831. База и резервные копии находятся в постоянном томе `avari-data`; контейнер работает от UID 10001. Остановка и пересоздание контейнера сохраняют данные. Не удаляйте том при обновлении.

Для HTTPS настроить DNS домена на VPS, скопировать `.env.example` в `.env`, установить `AVARI_ORIGIN=https://ваш-домен` и `AVARI_DOMAIN=ваш-домен`, включить `AVARI_TRUST_PROXY=true` для bundled proxy, затем:

```sh
docker compose --profile https up --build -d
```

Caddy обслуживает 80/443 и автоматически получает TLS-сертификат. Go-порт привязан к loopback; в браузере использовать внешний домен. Для VPS с существующим OpenResty и релизов через GitHub Actions используйте [`deploy/README.md`](../deploy/README.md).

## Установка без Docker

1. На VPS создать системного пользователя `avari` без интерактивного входа. Каталоги `/var/lib/avari` и `/var/lib/avari/backups` принадлежат ему с правами `0700`.
2. Поместить подходящие Linux-бинарники из `make release` в `/opt/avari` с правами на исполнение.
3. Скопировать `deploy/avari.env.example` в `/etc/avari/avari.env` и настроить домен. Файл доступен только root и группе avari (`0640`).
4. Установить `deploy/avari.service` в `/etc/systemd/system`, выполнить `sudo systemctl daemon-reload` и `sudo systemctl enable --now avari`.
5. Установить Caddy из официального репозитория, заменить домен в `deploy/Caddyfile`, включить reverse proxy. `AVARI_TRUST_PROXY=true` использовать только при недоступности backend-порта извне.
6. Запускать TUI через `sudo -u avari env AVARI_DB=/var/lib/avari/avari.db AVARI_BACKUPS=/var/lib/avari/backups /opt/avari/avari-admin`. Доступ к этой команде и каталогу базы предоставить только администратору VPS.

Проверка готовности: `/readyz`; живости: `/healthz`. Логи: `journalctl -u avari` или `docker compose logs app`. Graceful shutdown ждёт завершения HTTP-запросов. Новые миграции должны сопровождаться резервной копией перед обновлением; не заменять базу пустым файлом.

## TUI и резервные копии

Навигация: `Tab`/`1–4` разделы, `↑↓` выбор, `/` поиск, `f` фильтр пользователей, `r` обновление, `q` выход. `a` одобрение, `b` блокировка, `u` разблокировка, `p` новый пароль, `x` отзыв сессий, `n` резервная копия. Все изменяющие операции подтверждаются Enter; Esc отменяет.

Копирование выполняется через `VACUUM INTO`, а не копированием работающего SQLite-файла. Перед восстановлением проверяются целостность и версия схемы. Восстановление требует эксклюзивной файловой блокировки: остановите сервер и другие TUI. Предыдущая база автоматически копируется; все сессии в восстановленной базе отзываются до атомарной замены.

Для Docker: `docker compose stop app`, затем `docker compose run --rm admin`, раздел резервных копий, выбрать файл и Enter. После выхода `docker compose start app`. Для systemd аналогично остановить сервис, запустить TUI и затем снова включить сервис. Резервные копии находятся рядом с базой по умолчанию; регулярно копируйте их на отдельный защищённый носитель.

## Конфигурация

`AVARI_ADDR` — адрес прослушивания (по умолчанию `127.0.0.1:47831`); `AVARI_DB` — файл базы (`data/avari.db`); `AVARI_BACKUPS` — каталог копий для TUI; `AVARI_ORIGIN` — внешний origin (`http://localhost:47831`); `AVARI_TRUST_PROXY` — доверять `X-Real-IP` для ограничения попыток входа (по умолчанию false). Production требует HTTPS; cookie Secure включается автоматически для HTTPS-origin. Сессии истекают через 30 дней.


Для Web Push уведомлений на сервере задаются:
- `AVARI_VAPID_PUBLIC_KEY` — 65 байт uncompressed P-256 точки в base64url.
- `AVARI_VAPID_PRIVATE_KEY` — 32 байта scalar в base64url.
- `AVARI_VAPID_CONTACT` — контакт администратора (`mailto:email` или `https://url` без учетных данных).
Если все три переменные пусты, push-уведомления на сервере безопасно отключены. Если заданы не полностью или некорректны, сервис завершает работу с понятной ошибкой при запуске.

Группы откликов доступны над таблицей в виде переключателей с иконками папок. Выбор группы ограничивает список и статистику всеми её записями после текущих фильтров; пагинация применяется внутри выбранной группы. Сайт и расширение используют общую синюю палитру Arctic Depths; тёмная тема включена по умолчанию.

## PWA, автономный режим и Web Push

### Установка PWA
Avari.Jobs поддерживает установку в качестве Progressive Web App (PWA) на десктопные ОС (Chrome, Edge) и мобильные устройства (Android Chrome, iOS Safari «На экран Домой»):
- Статические ресурсы (HTML, JS, CSS, иконки) прекэшируются Service Worker для мгновенного холодного старта.
- При появлении новой версии в интерфейсе отображается явный запрос на обновление (баннер «Доступна новая версия»). Перед перезагрузкой страницы несохранённые локальные черновики принудительно сбрасываются в IndexedDB, предотвращая потерю введённого текста.
- PWA устанавливает только клиентское веб-приложение: сервер и база данных продолжают работать на выбранном хосте (`jobs.avari.dev` или ваш собственный сервер). В отличие от нативного десктопного лаунчера (Tauri), PWA не содержит локального Go-сервера и SQLite-базы данных.

### Офлайн-режим (IndexedDB)
- **Сохранение черновиков:** черновики создания и редактирования вакансий, задач и заметок сохраняются в IndexedDB автоматически при вводе. Черновики изолированы по аккаунту и восстанавливаются при возврате к форме. При выходе из аккаунта (Logout) все черновики удаляются.
- **Офлайн-чтение журнала (Opt-in):** автономный просмотр журнала отключён по умолчанию. Пользователь может включить его в **Настройки → Общие → Офлайн-режим**. При включении в локальной IndexedDB кэшируются последние загруженные списки вакансий, задач, событий календаря и открытые карточки откликов.
- **Отсутствие очереди офлайн-мутаций:** в приложении намеренно нет фоновой очереди отложенной записи (offline write queue) для предотвращения скрытых конфликтов и потери данных. Создание и редактирование вакансий на сервере требуют активного подключения к сети.
- **Очистка данных:** при выходе из аккаунта (Logout) или по кнопке «Очистить офлайн-кэш» в настройках локальные данные и черновики полностью удаляются. Серверные сессионные токены в офлайн-кэш не сохраняются.

### Системный Share Target (Поделиться)
- На поддерживаемых мобильных браузерах (Android Web Share Target) страница вакансии может передаваться в Avari.Jobs через системное меню «Поделиться».
- Поддержка системного Share Target зависит от ОС и браузера (на ряде платформ, включая iOS Safari и настольные браузеры, системная интеграция ограничена платформой).
- При отсутствии нативной поддержки доступна форма ручной вставки ссылки («Вставить ссылку» на главной).
- Автоматического сохранения вакансии при получении ссылки не происходит: открывается форма предпросмотра, где пользователь подтверждает сохранение.
- Срок жизни ожидающей ссылки (TTL) составляет 15 минут, после чего неиспользованная ссылка сбрасывается.

### Цель на день: 10 действий
Цель продуктивности рассчитывается каждый день; push-дайджесты приходят по будням:
- **Цель:** 10 полезных действий за день в часовом поясе аккаунта.
- **Правила начисления:**
  - Новая созданная вакансия: +1 балл.
  - Первый зафиксированный отклик по вакансии: +1 балл (создание вакансии сразу на этапе «Отклик» даёт 2 балла: 1 за создание + 1 за отклик).
  - Первое выполнение задачи или собеседования: +1 балл.
  - Повторные изменения этапов вакансии, закрытие вакансий или повторные отметки задач баллов не начисляют.
  - Импорт исторического журнала инициализируется с 0 баллов и не искажает текущую дневную цель.

### Web Push уведомления
- **Подписка:** включается только по явному клику пользователя в **Настройки → Общие → Push-уведомления**. Запрос разрешения браузера вызывается исключительно при клике.
- **Расписание дайджестов:**
  - Понедельник — пятница в **09:00** (по часовому поясу аккаунта): утренний план (количество запланированных задач и собеседований на день, цель 10 действий).
  - Понедельник — пятница в **18:00** (по часовому поясу аккаунта): вечерние итоги (выполнение запланированного, добавленные вакансии, отклики и общий прогресс N из 10 действий).
- **Безопасность и приватность:** тело push-уведомления содержит *только агрегированные счетчики*. Имена компаний, вакансий, контактов и конфиденциальные заметки в push никогда не передаются.
- **Требования к окружению:** для работы Web Push сервер должен быть запущен с валидными VAPID-ключами, а подключение клиента должно происходить по защищённому контексту (HTTPS или `localhost`).
- **Сроки доставки:** фактическое время доставки уведомления зависит от энергосбережения ОС, мобильной сети и push-сервиса вендора (Apple APNs, Google FCM, Mozilla).
- **Индивидуальные напоминания:** точечные push-напоминания по отдельным событиям календаря в текущей версии отсутствуют; для точных напоминаний используйте подписку на ICS-календарь в стороннем календаре.

### API Web Push и Daily Summary
Бэкенд предоставляет следующие эндпоинты (требуют авторизации):
- `GET /api/v1/push/config`: возвращает `{ "enabled": boolean, "publicKey": string, "subscribed": boolean }`.
- `POST /api/v1/push/subscribe`: принимает `{ "endpoint": string, "keys": { "p256dh": string, "auth": string } }` и регистрирует устройство.
- `POST /api/v1/push/unsubscribe`: принимает `{ "endpoint": string }` и удаляет подписку.
- `POST /api/v1/push/test`: опционально принимает `{ "endpoint": string }` и ставит тестовое push-уведомление в очередь доставки.
- `GET /api/v1/daily-summary`: возвращает агрегированные поля за текущий день (`today`, `timezone`, `goal`, `added`, `applied`, `completedTasks`, `completedInterviews`, `total`, `plannedTasks`, `plannedInterviews`, `completedTodayTasks`, `completedTodayInterviews`).

## Вкладки плагина

Плагин открывается по значку расширения на любом обычном HTTP/HTTPS-сайте. На неподдерживаемой странице только вкладка «Страница» сообщает, что данные не распознаны; «Вакансии», «Задачи», «Изменения» и «Настройки» доступны после входа. Настройки подключения и оформления доступны и до входа. На служебных страницах браузера и при запрете встраивания открывается отдельное окно расширения, связанное с исходной вкладкой.

Во вкладке «Настройки» находятся выбор онлайн/локального хранения, адреса сервисов, тема, системные уведомления и выход из аккаунта. Смена сервера требует повторного входа; сохранение прежнего адреса сохраняет сессию.

## Избранное и применение изменений

На hh.ru расширение распознаёт избранное в открытой карточке вакансии, списках `/applicant/vacancies`, `/applicant/favorite`, `/applicant/favorites?tab=vacancies` и отмеченных строках поиска. Пустой список также поддерживается. Добавлено чтение сохранённых вакансий LinkedIn (`/my-items/saved-jobs`, `/jobs/collections/saved`) и Hirify (`/account/favorites`). На странице списка `/vacancies` Хабр Карьеры читаются только карточки с активной отметкой избранного. Обрабатываются только загруженные строки; отсутствие вакансии на странице не снимает отметку в журнале.

Публичная проверка 17.10.2026 подтвердила маршрут Hirify по клиентскому роутеру и отметку Хабр Карьеры `data-active`. Авторизованные списки LinkedIn и Hirify проверяются на DOM-fixtures; проверка реальной разметки после входа остаётся необходимой при изменениях сайтов. На Getmatch и Geekjob отдельный список избранного в публичном интерфейсе не подтверждён, маршруты `/favorites` возвращают 404; автоматическое чтение избранного для них не заявляется. Остальные вкладки расширения доступны на обоих сайтах.

Если вакансии ещё нет в журнале, в «Предложениях» появляется предложение сохранить её на этапе «Сохранена», без даты отклика. После подтверждения в строке таблицы отображается сердечко. Избранное хранится отдельно от этапа и статуса отклика.

Кнопка «Применить всё» на странице предложений применяет все ожидающие предложения. Если запись изменилась или возникла ошибка, предложение остаётся для проверки; успешно применённые изменения сохраняются.

Кнопка «Проверить» в настройках уведомлений сообщает о постановке тестового сообщения в очередь, а не о фактической доставке. Отключение разрешения на офлайн-чтение удаляет только копии журнала, сохраняя черновики; выход или отказ авторизации удаляет оба вида данных. После восстановления сети отправка изменений становится доступна только после успешной проверки сессии на сервере. Сводка цели доступна каждый день; автоматические дайджесты отправляются по будням.
