# Первая публикация Avari.Jobs

Сайт: https://jobs.avari.dev. Политика конфиденциальности: https://jobs.avari.dev/privacy.html (статическая страница для CWS). Инструкция установки: https://jobs.avari.dev/extension.

## Карточка

Название: **Avari.Jobs — журнал откликов**.

Краткое описание: **Сохраняйте вакансии с популярных карьерных сайтов в личном журнале откликов.**

Описание:

> Avari.Jobs помогает вести структурированный поиск работы: сохранять вакансии, отмечать этапы отбора, планировать собеседования и фиксировать заметки.
>
> Расширение анализирует открытую страницу вакансии и предлагает сохранить её в журнал Avari.Jobs в один клик. На страницах ваших откликов можно сверять информацию с журналом и актуализировать статусы. Мини-окно открывается прямо из панели браузера.
>
> Для работы необходим аккаунт Avari.Jobs. По умолчанию расширение подключается к сервису jobs.avari.dev; также поддерживается подключение к собственному серверу («Использовать свой сервер» на экране авторизации).
>
> Расширение не отправляет отклики автоматически, не собирает пароли, файлы cookies или личную переписку. Все данные передаются исключительно на выбранный вами сервер Avari.Jobs. Инструкция по установке и началу работы: https://jobs.avari.dev/extension

Категория: продуктивность. Язык: русский. Иконка 128×128: `apps/extension/public/brand/icon-128.png`. Готовые изображения 1280×800: [расширение](chrome-store-assets/extension-1280x800.png) и [журнал](chrome-store-assets/journal-1280x800.png). Они показывают настоящий интерфейс с демонстрационными данными. Для обновления материалов выполнить `make e2e`, затем `node scripts/store-media.mjs`.

Рекламные изображения (JPEG, RGB, без альфа-канала):

- Маленькое, 440×280: [promo-small-440x280.jpg](chrome-store-assets/promo-small-440x280.jpg).
- Очень большое, 1400×560: [promo-marquee-1400x560.jpg](chrome-store-assets/promo-marquee-1400x560.jpg).

Оба изображения создаются тем же скриптом `node scripts/store-media.mjs` в фирменном стиле. Широкое изображение использует реальные скриншоты расширения и журнала с демонстрационными данными.

## Обоснование разрешений

- `storage`: адрес сервера, токен входа, настройки и локальные черновики.
- `activeTab`, `scripting`: открыть мини-окно расширения на выбранной пользователем странице и взаимодействовать с ней.
- Optional host permissions: пользователь выбирает свой HTTPS-сервер Avari.Jobs; доступ запрашивается к выбранному адресу. Localhost предназначен для собственного сервера и разработки.
- `notifications`: необязательные уведомления, включаемые пользователем.
- Host permission `https://jobs.avari.dev/*`: подключение production-расширения к серверу журнала без дополнительной настройки адреса.
- Content scripts: извлечение показанных в DOM данных на поддерживаемых страницах вакансий и откликов. Скрипты не переходят по страницам и не обращаются к закрытым API площадок.

Заполнить раздел Privacy по фактическому поведению: учётные данные входа передаются выбранному серверу; расширение обрабатывает сведения о вакансиях, этапах отклика, задачи, заметки и черновики. Токен хранится локально в Chrome. Данные не продаются и не используются для рекламы. Не отмечать «данные не собираются»: сведения о вакансии и отклике передаются в Avari.Jobs.

## Действия владельца аккаунта

1. Зарегистрироваться в [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole), оплатить регистрационный сбор и включить двухэтапную проверку Google.
2. Создать карточку, загрузить ZIP из GitHub Release, заполнить Store listing и Privacy.
3. Создать отдельный аккаунт для проверки Google на рабочем сервере и одобрить его через TUI. Указать логин, пароль и инструкции для входа только в закрытом разделе кабинета. Проверяющему нужно открыть поддерживаемую вакансию, запустить мини-окно, сохранить запись и открыть её в журнале.
4. Отправить первую версию на проверку. До одобрения пользоваться ZIP с сайта.

## Подключение обновлений через GitHub Actions

1. В Google Cloud включить Chrome Web Store API и IAM Service Account Credentials API. Создать service account, предоставить ему возможность создавать собственный access token (`roles/iam.serviceAccountTokenCreator` на самом service account).
2. Связать email service account с издателем в Developer Dashboard. Получить publisher ID и extension ID.
3. В GitHub environment `chrome-web-store` добавить secret `CHROME_SERVICE_ACCOUNT_JSON` и variables `CHROME_SERVICE_ACCOUNT_EMAIL`, `CHROME_PUBLISHER_ID`, `CHROME_EXTENSION_ID`. Ключ не добавлять в репозиторий.
4. Запустить **Publish Chrome extension**, указать успешно развёрнутый тег `vX.Y.Z`. Workflow скачает существующий архив, проверит SHA256 и отправит его на проверку Google. Он не пересобирает расширение.
5. После появления публичной карточки добавить repository variable `CHROME_STORE_URL` с её HTTPS-ссылкой. Следующий релиз сайта покажет кнопку магазина.

`CHROME_AUTO_PUBLISH=false` уже задан. Для автоматической отправки будущих релизов после успешного деплоя поменять его на `true`. Ошибка магазина не откатывает сайт; модерация Google выполняется отдельно.

Документация: [первая публикация и API](https://developer.chrome.com/docs/webstore/using-api), [service accounts](https://developer.chrome.com/docs/webstore/service-accounts).
