# MVP: журнал откликов на hh.ru

> **Исторический документ (PRD фазы MVP):** Отражает первоначальные требования и границы пилотного MVP проекта от октября 2026 года. Фактическая реализованная функциональность системы существенно расширена: поддержаны дополнительные карьерные площадки, PWA с автономным чтением и черновиками, Web Push уведомления, автозаполнение вакансий по ссылке, учет ежедневной цели (10 действий), подписной ICS-календарь, локальные десктопные сборки (Tauri) и управление резюме. Интеграция с Telegram-ботом запланирована в дорожной карте развития сервиса.

## Цель
Mobile-first веб-приложение для ведения журнала вакансий и откликов. Основной способ заполнения — браузерное расширение, которое парсит открытую страницу hh.ru и предлагает добавление записи или изменение состояния.

Изменения сохраняются только после подтверждения пользователя. На hh.ru приложение ничего не меняет.

## Стек
- Backend: Go, один сервис.
- База данных: SQLite.
- Frontend: React или Vue.
- Расширение: Chromium, Manifest V3.
- Размещение: существующий VPS.
- Администрирование: отдельное консольное TUI-приложение.

## Границы MVP
Входит:
- Регистрация с ручным одобрением.
- Отдельная авторизация на сайте и в расширении.
- Добавление вакансий вручную и через расширение.
- Предложения изменения состояний по данным открытой страницы.
- Этапы поиска, история, заметки и задачи.
- Календарь на семь дней: сегодня и следующие шесть дней.
- До пяти custom-полей и до 1000 записей на пользователя.

Не входит:
- LLM и распознавание речи.
- Telegram-бот (запланирован в дальнейшей дорожной карте; в исходный MVP не входил).
- API hh.ru и фоновый обход страниц.
- Автоматические действия на hh.ru.
- Сохранение переписки из чата.
- Вложения, сложная аналитика и настраиваемая воронка.

## Основные сценарии
### Регистрация
1. Пользователь регистрируется по email и паролю.
2. Аккаунт получает состояние `pending`.
3. Администратор одобряет аккаунт через TUI.
4. Пользователь получает доступ к сайту и может войти в расширение.

Состояния аккаунта: `pending`, `active`, `blocked`.
Восстановление доступа — через администратора.

### Добавление вакансии
1. Пользователь открывает вакансию hh.ru.
2. Расширение извлекает доступные данные.
3. Предлагает добавить запись.
4. Пользователь проверяет поля и выбирает «Сохранена» или «Отклик отправлен».
5. Приложение сохраняет запись и событие истории.

Повторное добавление той же вакансии открывает существующую запись.

### Изменение состояния
1. Расширение обнаруживает состояние отклика на поддерживаемой открытой странице.
2. Сравнивает его с последним наблюдением.
3. Создаёт предложение изменения.
4. Пользователь применяет, редактирует или отклоняет предложение.
5. Применённое изменение сохраняется в истории.

### Ручное управление
На сайте и через расширение пользователь может редактировать запись, изменить этап, добавить заметку, создать задачу, принять или отклонить предложение.

## Данные
### Запись вакансии
| Поля | Описание |
|---|---|
| Компания, позиция | Основные данные |
| Ссылка, ID hh.ru | Сопоставление и защита от дублей |
| Дата сохранения, дата отклика | Даты процесса |
| Этап | Сохранена / Отклик / HR / Интервью / Финал / Оффер |
| Состояние процесса | Активен / Приостановлен / Закрыт |
| Результат закрытия | Отказ работодателя / Мой отказ / Вакансия закрыта / Оффер принят / Другое |
| Зарплата | Сумма или диапазон, валюта, период, gross/net |
| Локация, формат работы | Необязательные поля |
| Контакт рекрутера | Необязательное ручное поле |
| Заметки | Пользовательский текст |
| Custom-поля | До пяти на пользователя |

Внешнее состояние hh.ru хранится отдельно от пользовательского этапа.

### Custom-поля
Типы: текст, число, дата, флаг, выбор из списка.
Начальный набор: приоритет, интерес к роли, масштаб ответственности, соответствие опыту, риски.
Пользователь может изменить названия и состав полей. Смена типа заполненного поля не входит в MVP.

### Связанные сущности
- История: дата, событие, изменения, источник `manual` или `extension`.
- Задача: название, дата, необязательное время, вакансия, состояние `open/done`.
- Наблюдение: найденное состояние hh.ru, URL, время.
- Предложение: текущие и новые значения, состояние `pending/applied/dismissed`.

## Правила
- Все данные принадлежат конкретному пользователю; доступ проверяется backend.
- Одна вакансия hh.ru — одна запись на пользователя.
- Открытие вакансии не считается откликом.
- Отсутствие вакансии на странице не считается отказом.
- Повторный парсинг не создаёт одинаковых предложений.
- Повторное подтверждение не дублирует события.
- Ручные данные не перезаписываются без подтверждения.
- Неизвестное состояние не преобразуется в этап автоматически.
- При конфликте изменений показывается актуальное сравнение.
- Cookies, пароль и сессия hh.ru не передаются в приложение.
- Расширение работает только с открытыми страницами.
- Сайт остаётся полностью работоспособным без расширения.

## Администрирование через TUI
Отдельное консольное приложение на VPS. Без веб-админки и административных sh-скриптов.

Разделы: заявки на регистрацию, пользователи, административный журнал, резервные копии.

Операции:
- Одобрение регистрации.
- Блокировка и разблокировка.
- Сброс пароля.
- Отзыв пользовательских сессий.
- Создание резервной копии.
- Восстановление из резервной копии.

TUI использует общую административную логику backend. Доступ — только администратору VPS. Все административные изменения журналируются.

## Критерии готовности
- Регистрация и одобрение через TUI работают.
- Неодобренные и заблокированные аккаунты не имеют доступа.
- Пользователь может войти на сайт и в расширение.
- Вакансия добавляется с открытой страницы без ручного копирования основных полей.
- Дубли записей и предложений исключены.
- Изменения применяются только после подтверждения.
- Журнал, история, задачи и календарь работают без расширения.
- Пользовательские данные изолированы.
- Резервное копирование и восстановление SQLite проверены.

## Расширение источников (11 октября 2026)

Помимо hh.ru поддерживаются карточки вакансий LinkedIn, Getmatch и Hirify. Сопоставление выполняется по площадке и ID из нормализованной ссылки, без дублей при изменении параметров перехода или названия в URL. `hhId` относится только к hh.ru. Наблюдения новых площадок содержат `vacancyUrl`; прежний формат наблюдений hh.ru сохраняется. Изменение этапа по внешнему состоянию по-прежнему требует индивидуального подтверждения. Списки откликов поддерживаются для hh.ru, Getmatch и Hirify; возможности чтения карточек и ограничения новых площадок описаны в README.

## Реализованная эволюция системы (состояние после MVP)
- **Расширение карьерных сайтов:** карточки Geekjob и Хабр Карьеры; избранное hh.ru, LinkedIn, Hirify и Хабр Карьеры.
- **Автозаполнение вакансий по ссылке:** бэкенд `/api/v1/vacancies/preview` извлекает метаданные (OpenGraph, JobPosting JSON-LD, DOM) по вставленной ссылке, форма предпросмотра позволяет подтвердить сохранение.
- **PWA и автономность:** поддержка установки PWA, Service Worker для офлайн-старта, сохранение черновиков и защищённое чтение журнала через IndexedDB.
- **Дневная цель и Web Push:** ежедневный подсчёт цели (10 действий) и дайджесты в 09:00 и 18:00 по будням.
- **Календарные подписки:** секретные ссылки `.ics` для внешних сервисов (Apple, Google, Яндекс).
- **Десктопные приложения:** локальные установщики Tauri для Windows и macOS с фоновым Go-сервером и SQLite.
- **Управление резюме:** хранение и версионирование оригиналов резюме в БД.
- **Дорожная карта:** интеграция с Telegram-ботом запланирована в будущих релизах.
