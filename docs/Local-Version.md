# Локальная версия Avari.Jobs

Локальная версия — установленное приложение с иконкой в трее и привычным интерфейсом в браузере. Данные хранятся на вашем компьютере, отдельно от jobs.avari.dev. Пользователю не нужны Go, Node.js, Docker или терминал.

[Визуальный помощник](https://ostkost.github.io/avari-job-applications/) · [Скачать приложение](https://github.com/OstKost/avari-job-applications/releases/latest)

Текущие публичные сборки не подписаны сертификатом издателя и не прошли notarization Apple. ОС может показывать предупреждение или ограничивать запуск; скачивайте файлы из официального релиза. Онлайн-версия доступна без установки.

## Установка и первый запуск

1. Установите Avari.Jobs: Windows x64 — установщик `.exe`; macOS 13+ (Intel или Apple Silicon) — соответствующий `.dmg`, затем перенесите Avari.Jobs в «Программы».
2. Запустите Avari.Jobs по иконке. Приложение проверит каталог данных, базу и локальный порт и откроет браузер.
3. Создайте личный аккаунт с email и паролем. Подтверждение через административную консоль не требуется. Сохраните пароль для входа в браузере и расширении.
4. При желании включите запуск при входе в систему. Переключатель всегда доступен в **Настройки → Общие → Локальный Avari.Jobs**. Отключение автозапуска не останавливает уже работающий сервис.
5. Установите расширение из магазина или распакуйте архив, включите режим разработчика в `chrome://extensions` и выберите «Загрузить распакованное расширение». Оба способа поддерживаются.
6. В расширении выберите «Локальное сохранение», войдите с созданным аккаунтом. Проверка подключения появляется после входа. Этот шаг можно пропустить.

Адрес по умолчанию — `http://127.0.0.1:47831`. При занятом порте лаунчер предложит указать другой. Новый адрес нужно также сохранить в расширении.

## Повседневная работа

Закрытие браузера не останавливает Avari.Jobs. Повторный запуск по иконке открывает существующий экземпляр. При автозапуске сервис работает в фоне и не открывает браузер самостоятельно.

Меню значка в трее: состояние сервиса, открытие Avari.Jobs, настройки, перезапуск, диагностика и завершение. На macOS значок находится в строке меню. Если расширение не может подключиться, запустите Avari.Jobs по иконке.

Каталог данных можно открыть из диагностики лаунчера. Там находятся `avari.db`, настройки порта `launcher.json`, `server.log` и резервные копии в `backups`. Расположение:

- Windows: `%LOCALAPPDATA%\dev.avari.jobs.local`.
- macOS: `~/Library/Application Support/dev.avari.jobs.local`.

Установка новой версии сохраняет этот каталог. При ручной установке новой версии сначала завершите Avari.Jobs через меню трея. Перед миграциями существующая база автоматически копируется и проверяется. Если создание копии или миграция не удалась, сервис не начинает обслуживать запросы.

Для восстановления сохраните весь каталог данных, завершите лаунчер и обратитесь к инструкции [резервного копирования](Usage.md#tui-и-резервные-копии). Не заменяйте работающую SQLite-базу и не удаляйте данные приложения для устранения ошибки установки. Экспорт JSON позволяет восстановить личный журнал в новом аккаунте через настройки без использования административной консоли.

Внешние календарные сервисы не могут прочитать localhost. Для подписки им нужен доступный извне HTTPS-сервер. Локальная версия не синхронизирует данные с онлайн-версией автоматически.

> **Отличие PWA и нативного десктопного приложения:** веб-интерфейс Avari.Jobs можно установить как PWA (Progressive Web App) прямо из браузера на рабочий стол или мобильное устройство. PWA устанавливает клиентскую веб-оболочку с поддержкой офлайн-чтения и черновиков, но серверная часть и база данных остаются на выбранном хосте (например, на `jobs.avari.dev` или вашем удалённом сервере). Нативное приложение (установщики `.exe` / `.dmg` на базе Tauri) — это отдельный автономный пакет, который запускает собственный локальный Go-сервер и локальную SQLite-базу на вашем компьютере. Автоматической синхронизации между локальной базой десктопа и удалённым сервером нет; для переноса данных используется ручной экспорт/импорт JSON.


## Импорт и экспорт

В **Настройки → Импорт и экспорт** можно скачать полный журнал JSON или выбрать ранее созданный экспорт. Раздел доступен как в онлайн-версии, так и локально. CSV-экспорт выборки вакансий остаётся в журнале.

JSON включает вакансии, их группы и теги, дополнительные поля, задачи, заметки, историю, часовой пояс и настройки отображения текущего браузера. Пароли, сессии, ссылки подписки и скачивания, неподтверждённые предложения расширения не экспортируются.

Импорт дополняет текущий журнал:

- Вакансии сопоставляются по сохранённому происхождению, затем по нормализованной ссылке. Компания и позиция без ссылки не считаются достаточным совпадением.
- Текущие поля совпавшей вакансии сохраняются. Отсутствующие задачи, заметки и события добавляются. Изменённые текущие записи не перезаписываются.
- Повторный импорт и перенос через промежуточный экземпляр не создают дубли. Ранее удалённые связанные записи не восстанавливаются повторным импортом.
- Поля сопоставляются автоматически по названию и совместимому определению. При конфликте выберите совместимое поле, создание нового в пределах лимита либо явно исключите поле вместе с его значениями.
- Применение часового пояса, темы и отображения выбирается отдельно; по умолчанию текущие настройки сохраняются.

Перед применением показывается отчёт. После изменения журнала или параметров импорта нужен новый предпросмотр. Применение выполняется целиком: ошибка отменяет все изменения. Сохраняются лимиты 1000 вакансий и 5 дополнительных полей. Размер загружаемого JSON — до 31 МБ; дополнительные защитные лимиты файла — 50 000 задач и заметок суммарно, 100 000 событий истории. Поддерживается формат `avari-journal`, версия 1.

## Сборка для разработчиков

Нужны инструменты обычной сборки проекта, Rust stable (не ниже 1.90) и платформенные зависимости Tauri. Для macOS нужны Xcode Command Line Tools; для Windows — Microsoft C++ Build Tools и Windows SDK. Это требования сборки, не требования для конечного пользователя.

```sh
npm ci
npm run desktop:dev
npm run desktop:build
# Только приложение macOS, без DMG:
npm run desktop:build -- --bundles app -- --locked
```

Скрипт готовит веб-интерфейс, архив расширения и Go sidecar для текущей платформы. Установщики находятся в `apps/desktop/src-tauri/target/release/bundle`. Поддерживаемые target: `x86_64-pc-windows-msvc`, `aarch64-apple-darwin`, `x86_64-apple-darwin`. Для выбора target задайте `AVARI_DESKTOP_TARGET` и передайте тот же `--target` в сборку Tauri. Для Cargo используется `-- --locked` после аргументов Tauri.

Обычный серверный бинарник продолжает работать с прежними настройками. Персональный режим включается только явным `--personal`; он требует matching loopback origin и секрет первого запуска `AVARI_SETUP_TOKEN`. `--launcher` дополнительно включает остановку через stdin (`shutdown` или EOF) и защищённый нативный канал настроек. Эти секреты существуют только в памяти процессов.

## CI и подпись релизов

`desktop.yml` собирает установщики и запускает Go/Rust-проверки на Windows и обеих архитектурах macOS. Pull request и обычные сборки создают проверочные артефакты без публичного выпуска. Серверный workflow остаётся самостоятельным.

Для подписанного desktop-релиза включите repository variable `AVARI_DESKTOP_SIGNING_ENABLED=true` и настройте secrets:

- Windows: `AVARI_WINDOWS_CERTIFICATE` (Base64 PFX), `AVARI_WINDOWS_CERTIFICATE_PASSWORD`. Нужен сертификат, поддерживающий этот способ импорта; для аппаратного или облачного провайдера адаптируйте native signing configuration к его инструменту.
- macOS: `AVARI_APPLE_CERTIFICATE` (Base64 Developer ID P12), `AVARI_APPLE_CERTIFICATE_PASSWORD`, `AVARI_APPLE_SIGNING_IDENTITY`, `AVARI_APPLE_ID`, `AVARI_APPLE_PASSWORD` (пароль приложения), `AVARI_APPLE_TEAM_ID`.
- `CHROME_STORE_URL` задаёт ссылку магазина. Без неё ручная установка остаётся доступной, а магазин отображается как ожидающий публикации.

Установщики со стабильными именами и `DESKTOP-SHA256SUMS` добавляются к существующему GitHub Release каждого тега. Без включённой подписи публикуются неподписанные сборки. Отсутствие сертификатов не блокирует выпуск; если подпись включена, необходимые сертификаты обязательны. Обновление из приложения описано ниже; первая версия с updater устанавливается вручную.

## Обновления и «Что нового»

В установленном приложении откройте **Настройки → Общие → Обновления приложения**. Лаунчер проверяет стабильные выпуски через GitHub после запуска и затем раз в сутки; ручная проверка доступна в любое время. Проверка передаёт обычный сетевой запрос к GitHub, без данных журнала и учётных данных Avari.Jobs.

Уведомление можно отложить на семь дней. Следующая версия получает отдельное уведомление. «Скачать версию» загружает пакет и проверяет подпись, пока приложение продолжает работать. «Установить и перезапустить» останавливает сервис и устанавливает пакет. Перед этим сохраните открытые формы во всех вкладках и расширении. После запуска обновлённого сервиса перезагрузите интерфейс предложенной кнопкой. При закрытии приложения загруженный пакет не сохраняется: его нужно скачать заново.

«Что нового» доступно из меню и настроек как локально, так и онлайн. История включена в приложение и доступна без интернета. Индикатор появляется после смены версии и снимается при открытии истории; на первом посещении история не считается непрочитанной. Состояние просмотра хранится для аккаунта в текущем браузере, напоминание об обновлении — в каталоге приложения.

Версии, выпущенные до появления updater, требуется один раз обновить вручную официальным установщиком. При недоступности сети приложение продолжает работать. При ошибке установки откройте диагностику из трея; при необходимости переустановите приложение, сохранив каталог данных. Автоматического отката базы нет.

### Подготовка выпуска с обновлением

1. Создайте `releases/X.Y.Z.json` с полями `version`, `date` (YYYY-MM-DD), `summary` и массивами `features`, `improvements`, `fixes`. Пишите краткие русские описания пользы для пользователя. Выполните `AVARI_VERSION=X.Y.Z node scripts/release-notes.mjs`.
2. Настройте GitHub Actions secret `AVARI_UPDATER_PRIVATE_KEY` с содержимым приватного ключа Tauri, соответствующего `plugins.updater.pubkey` в конфигурации. Для защищённого паролем ключа также нужен `AVARI_UPDATER_PRIVATE_KEY_PASSWORD`. Ключ подписи обновлений независим от сертификатов Windows/macOS; существующие настройки сертификатов сохраняются.
3. Первоначальный ключ этой реализации сохранён вне репозитория: `~/.local/share/avari-updater/signing.key` (права 0600). Публичный ключ находится рядом в `.pub` и встроен в приложение. Создайте защищённую резервную копию приватного ключа перед первым выпуском. Не заменяйте его после распространения приложения без отдельного плана перехода.
4. Для тега `vX.Y.Z` desktop workflow требует ключ, собирает три платформы, создаёт updater-пакеты и `.sig`. macOS использует `.app.tar.gz`, Windows — NSIS `.exe`. Обычные PR/main-проверки ключа не требуют.
5. Пакеты и контрольные суммы публикуются перед `desktop-update.json`. Манифест появляется только после успешной сборки всех платформ. После его публикации повторный запуск workflow сохраняет выпущенные пакеты без перезаписи. Пока он недоступен, проверка обновлений временно неуспешна. Ссылки внутри указывают на конкретный тег.

Перед первым публичным выпуском проведите обновление между двумя тестовыми версиями на Windows x64 и обеих архитектурах macOS, в том числе с изменённым портом, автозапуском и базой предыдущей схемы. Для проверки на тестовом канале используйте отдельную конфигурацию endpoint и тестовый ключ; не направляйте опубликованные приложения на тестовые пакеты.

## Возможности локального режима в 1.10.0

Настройка владельца и вход открываются сразу, без публичного лендинга и ссылки «На главную». Telegram, приглашение установить PWA, Web Push и панель дополнительного офлайн-кэша скрыты: основная база уже хранится на компьютере. Журнал, заметки, задачи, календарь, резюме, импорт и экспорт продолжают работать локально. Автозаполнение вакансии по ссылке требует доступа компьютера к интернету. Расширение подключается через «Локальное сохранение» и отдельный вход по email и паролю.
